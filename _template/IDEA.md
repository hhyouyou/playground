# IDEA · 一句话说清这个想法

> 复制这个文件到新 idea 目录，改成 `IDEA.md`，然后把下面每个字段填实。
> 填不出来的字段就是还没想清楚的地方——先想，再写代码。

| 字段 | 内容 |
| --- | --- |
| 目录 | `my-new-idea/` |
| 状态 | 💡 火花 |
| 开始日期 | YYYY-MM-DD |
| 最近更新 | YYYY-MM-DD |
| 一句话 | 谁，在什么场景下，用它解决什么问题 |
| 目标用户 | 具体到「哪一种人」，不要写「所有人」 |
| 它解决的问题 | 现在他们是怎么凑合解决的？为什么不够好？ |
| 关键假设 | 这个想法成立，必须为真的 1–3 件事 |
| 验证方式 | 用什么最小实验来检验假设？（找谁、做什么、看什么） |
| 毕业线 | 达成哪些**可观察的事实**，就认为它值得独立成项目 |
| 放弃条件 | 出现什么现象，就该停下（不是「没时间」） |
| 当前进度 | 已经做完什么，还差什么 |
| 下一步 | 只有一条，具体到能立刻开始 |
| 结论记录 | 每次验证后追加：日期 · 观察到什么 · 因此决定什么 |

## 填写参考

**关键假设**要写成「可以被证伪的句子」：

- ✅ 「同屏双人比单人更能带来重复游玩」
- ❌ 「它会很好玩」

**毕业线**要写成「可观察的事实」：

- ✅ 「连续一周至少有 3 次主动打开」「3 对试玩的朋友里有 2 对主动要求再来一局」
- ❌ 「做得差不多了」「用户反馈不错」

**放弃条件**要写成「现象」，不是「状态」：

- ✅ 「试玩两局后不再打开，且说不出具体缺陷」
- ❌ 「没时间就放弃」
