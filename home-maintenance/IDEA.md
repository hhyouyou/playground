# IDEA · 家庭维护助手 · Home Maintenance

| 字段 | 内容 |
| --- | --- |

| 状态 | 🧪 验证中 |

| 最近更新 | 2026-11-23 |
| 一句话 | 家里的滤芯、油污、水垢这类「没人记得、但忘了会出问题」的维护，交给它按周期提醒并留下记录 |
| 目标用户 | 自己管理家务的成年人，尤其是同时养着好几台需要换耗材的家电、又不想记 Excel 的人 |
| 它解决的问题 | 家电维护周期散落在说明书和记忆里，结果是滤芯超期、油烟机拖到积油、洗衣机发霉；现有提醒工具要么太重，要么只能做「一次性提醒」，不会算下一次 |
| 关键假设 | ① 人们真的愿意为「按时维护家电」花一点记录成本；② 通用周期任务（每 N 天 / 每周几 / 每月某日）比只服务加湿器的专用工具更有价值；③ 智能家居事件（湿度、滤芯寿命、设备离线）能显著降低记录负担，让产品从「要你填」变成「主动告诉你」 |
| 验证方式 | 自己在 DSH 里真实使用一周以上：是否每天会点开、完成记录是否准确、日历视图是否比手机自带提醒更好用；再邀请 1–2 位家人试用，观察他们会不会主动打开 |
| 毕业线 | ① 自己连续使用 14 天，其中至少 10 天有打开或完成记录；② 至少有 1 位家人独立使用并保留任务；③ 至少接入一种真实设备事件（只读即可），并因此生成过一条有意义的待办 |
| 放弃条件 | 复盘发现所有维护事项用系统日历就能解决，且插件本身没有带来任何额外价值（例如自动算下一次、统一查看） |
| 当前进度 | DSH 插件 `@local/dsh-home-maintenance` v1.0.1：左侧「家庭维护」入口、真实完成记录、自定义周期任务、可交互维护日历；数据存在浏览器本机，无需账号、无需构建；视觉方向（亮色、薄荷绿、圆润卡片）已确定并有预览稿 |

## 备注

- 插件安装返回 `applied`，但**实际显示、主题切换和运行交互仍需人工确认**——先把这一项确认掉，否则后面所有验证都建立在不确定的基础上。
- 演进顺序建议：先做「真实用一周」，再补通用任务数据结构（暂停、模板、更多周期规则），最后才碰智能家居接入。
- 智能家居的只读事件优先于设备控制；涉及控制时必须有权限、确认和审计，别让传感器误报直接驱动危险动作。
- 这个 idea 的形态很依赖宿主（DSH 插件）。若要毕业成独立产品，需要先想清楚「脱离 DSH 后是什么」——网页？手机 App？还是继续保持插件形态。
