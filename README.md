# playgrand · idea 孵化广场

> 一个想法先在这里活下来，再决定它要不要成为产品。

这里是个人 idea 孵化器。**根目录下的每个子文件夹，都是一个从想法长出来的小项目**。它们不需要完整、不需要有用户、也不需要赚钱——只要能回答一个问题就够了：

> 这个想法，值不值得我继续投入？

- 验证为真 → 用 `git subtree split` 拆成独立仓库，独立发展；
- 验证为假、或优先级下降 → 留在广场里归档，**结论也留下**，避免第二次踩同一个坑。

这个仓库存在的意义不是交付，而是**让试错成本足够低**。

## 3. 状态图例

| 状态 | 含义 | 该做什么 |
| --- | --- | --- |
| 💡 火花 | 只有一句想法，还没有代码 | 写 `IDEA.md`，别急着写代码 |
| 🔬 探针 | 正在做一个最小可行验证（spike） | 限定时间，只验证一个假设 |
| 🧪 验证中 | 有能跑的东西，在验证真实需求 | 找真人用，记录反馈 |
| 🚀 毕业 | 已验证可行，要独立成项目 | 拆仓库，保留历史 |
| 🅿️ 停放 | 暂时搁置，但没被否决 | 记一句「为什么停」 |
| 🗄️ 归档 | 已验证否决 | 记一句「为什么不行」 |

关键区别：**停放是没时间，归档是不该做**。两者都要写清原因，否则半年后你会重新做一遍。

## 4. 一个 idea 在广场里的规矩

1. **必须能独立跑起来**。每个 idea 目录自带依赖声明和自己的 `README.md`，不依赖广场根目录的任何东西。
2. **不建嵌套 git 仓库**。广场内所有代码都进这个仓库；需要独立时再拆（见第 6 节）。
3. **不提交依赖和本机状态**。`node_modules/`、`.pnpm-store/`、`dist/`、浏览器 profile 一律忽略。
4. **允许半成品**。但半成品必须写清「当前停在哪、下一步是什么」，否则它就是垃圾。
5. **结论优先于代码**。代码可以删，`IDEA.md` 里的验证结论不要删。

### 提交信息

不需要严格规范，但建议带上目录名，方便回溯：

```
gold-miner: 增加双人模式商店货架切换
home-maintenance: 修复日历翻月时丢失完成记录
docs: 补充晋级流程
```

## 5. 新增一个 idea

```powershell
# 1. 复制模板
Copy-Item -Recurse _template my-new-idea

# 2. 填登记卡：一句话、要验证的假设、毕业线、放弃条件
#    —— 这四件事想不清楚，就先别写代码

# 3. 写能跑的最小版本，然后加进上面的索引表

# 4. 提交
git add my-new-idea README.md
git commit -m "my-new-idea: 初始化 idea 骨架"
```

模板内容见 [`_template/IDEA.md`](_template/IDEA.md) 和 [`_template/README.md`](_template/README.md)。

## 6. 从广场毕业

当一个 idea 真正可行、要独立成项目时：

```powershell
# 1. 单独拆出一条只含该目录历史的分支
git subtree split -P gold-miner -b gold-miner-standalone

# 2. 在新目录建仓库并拉入历史
git init gold-miner-repo
cd gold-miner-repo
git pull ../playgrand gold-miner-standalone

# 3. 广场这边：删掉目录，索引表里的状态改为 🚀 毕业，并写上仓库地址
```

只删目录、不删记录。半年后你在索引表里还能看到「这个想法验证过，现在是独立项目」。

流程细节与检查清单见 [`docs/PLAYBOOK.md`](docs/PLAYBOOK.md)。

---

## 7. 每周十分钟巡检

- 有没有 idea 超过两周没动？→ 改成 🅿️ 停放，写一句原因。
- 有没有「其实早就不想做了」的？→ 改成 🗄️ 归档，写下否决理由。
- 有没有已经该毕业的？→ 拆出去。
- 索引表和实际目录对得上吗？→ 对不上就当场改。

广场的价值来自**诚实的状态**，而不是文件夹的数量。
