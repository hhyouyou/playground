# 孵化手册 · PLAYBOOK

广场的总览在根目录 [`README.md`](../README.md)。这份手册写的是**规则和流程**，用来在半年后还能看懂自己当初在想什么。

---

## 1. 广场的边界

广场是**试错场**，不是产品仓库。它的成功标准是「用最少的钱和时间，证明或否决更多想法」，不是「每个项目都能用」。

由此推出三条原则：

1. **先假设，后代码。** 一个 idea 的价值在于它验证了哪个假设，不在于写了多少行。
2. **允许粗糙。** 原型阶段用最直白的技术实现，不为未来可能的扩展提前抽象。
3. **写下来的结论才算数。** 没写下来的验证，等于没验证——三个月后你不会记得。

---

## 2. 目录约定

### 根目录

| 命名 | 含义 |
| --- | --- |
| `kebab-case/` | 一个 idea 项目 |
| `_` 前缀 | 广场自身的基础设施（模板、文档、参考），不进 idea 索引 |
| 单个 `.md` 文件 | 暂时性的笔记，能归档就归档 |

### 一个 idea 目录内部

没有强制结构，但有两个必须有：

| 文件 | 作用 | 不写会怎样 |
| --- | --- | --- |
| `IDEA.md` | 登记卡：假设、验证方式、毕业线、放弃条件、结论 | 半年后不知道自己为什么做它 |
| `README.md` | 项目文档：怎么跑、做了什么、现状与限制 | 自己都跑不起来 |

推荐（按需）：

```
my-idea/
├─ IDEA.md              必填 · 登记卡
├─ README.md            必填 · 项目文档
├─ docs/                可选 · 设计说明、决策记录、调研
├─ src/                 可选 · 源码
├─ tests/               可选 · 能自动跑的验证
└─ .gitignore           可选 · 目录级额外忽略规则
```

### 独立性

每个 idea 必须能脱离广场单独运行：自带依赖声明（`package.json` / `requirements.txt` / 纯静态 HTML），不引用广场根目录的文件。这样才能顺利毕业，也才能被单独打开看。

## 3. 登记卡怎么写

模板：[`_template/IDEA.md`](../_template/IDEA.md)。

四个字段决定它值不值得做，必须写实：

| 字段 | 好例子 | 坏例子 |
| --- | --- | --- |
| **关键假设** | 「同屏双人比单人更能带来重复游玩」 | 「它会很好玩」 |
| **验证方式** | 「让 3 对朋友各玩 20 分钟，观察是否主动要求再来一局」 | 「继续完善」 |
| **毕业线** | 「连续一周至少有 3 次主动打开」 | 「做得差不多了」 |
| **放弃条件** | 「试玩两局后不再打开，且说不出具体缺陷」 | 「没时间就放弃」 |

**毕业线 = 可观察的事实**，不是感觉。写不出可观察的毕业线，说明这个假设还不够具体，先别写代码。

## 4. 生命周期

```
💡 火花 ──写登记卡──▶ 🔬 探针 ──最小可用──▶ 🧪 验证中 ──达标──▶ 🚀 毕业
                          │                    │
                          └──── 否决 ────┬────┘
                                         ▼
                                    🗄️ 归档
                          （任何时候）──▶ 🅿️ 停放
```

### 💡 火花

- 只写 `IDEA.md`，不建代码目录。
- 一句话说不清「谁会在什么场景下用它」，就别往下走。
- 时间盒：一周内决定是进入探针还是直接归档。

### 🔬 探针

- 目标是**回答一个技术或体验上的未知**，不是做产品。
- 时间盒：1–3 天。超时就说明想法太大，需要切小。
- 允许一次性代码、允许丑，但要能跑给人看。

### 🧪 验证中

- 已经有能跑的东西，问题从「能不能做」变成「有没有人要」。
- 必须找**真人**用，而不是自己反复打磨。
- 每次验证后更新 `IDEA.md` 的「当前进度」与「结论记录」，并更新根目录索引表。

### 🚀 毕业

- 见第 5 节。
- 只有同时满足三条才毕业：
  1. 毕业线已达成，且有记录可查；
  2. 你愿意在接下来一个月持续投入；
  3. 它需要独立成长（有自己的用户、发布节奏或协作者），而不是继续待在广场。

第三条常被忽略：**做得再好，如果它只是「一个大点的玩具」，留在广场更省事**。

### 🅿️ 停放

- 不是失败，是排队。写清「为什么现在停」和「什么条件下会重新捡起来」。

### 🗄️ 归档

- 约定：**不删代码，只在 `IDEA.md` 顶部加一行归档原因**，索引表状态改 🗄️。
- 如果代码本身还有价值（组件、脚本），把可复用的部分挪到 `models/` 或其他共享位置。

---

## 5. 毕业：拆成独立仓库

### 为什么要拆

广场会越来越重：一次 clone 拿到所有 idea 的依赖，`git log` 里混着不相干的提交。当某个 idea 需要长期维护、发布或协作时，它应该有自己的仓库。

### 步骤（保留全部历史）

```powershell
# 在广场根目录：把该目录的历史单独抽成一条分支
git subtree split -P gold-miner -b gold-miner-standalone

# 建新仓库并拉入
git init ..\gold-miner
cd ..\gold-miner
git pull ..\playgrand gold-miner-standalone
git branch -M main

# 顺手补上新仓库的 README / LICENSE / CI，再 push
```

> `git subtree split` 只保留该目录下的提交历史，其他 idea 的历史不会带过去。旧写法 `git filter-branch --subdirectory-filter` 也能做到，但慢且已不推荐。

### 广场这边收尾

1. 删除目录：`git rm -r gold-miner`（历史仍在 `git log` 里，需要时能找回）。
2. 索引表状态改为 🚀 毕业，写上仓库地址和毕业日期。
3. `IDEA.md` 里补一句「毕业结论」：验证到了什么、新仓库在哪。
4. 提交：`git commit -m "gold-miner: 毕业，迁出到独立仓库"`

### 毕业检查清单

- [ ] 目录能脱离广场独立运行（依赖声明完整）
- [ ] 有 LICENSE 和 README
- [ ] 敏感信息、本机路径、个人数据已清理
- [ ] 大文件（模型、图片、视频）策略已定（Git LFS 或外部存储）
- [ ] 广场索引表已更新

## 6. 共享素材：`models/`

`models/` 是广场级的共享素材库，不是 idea。放**可被多个 idea 复用**的 3D 模型、程序化生成脚本、贴图。

规则：

- 每个模型一个子目录，自带生成/校验脚本，保证可复现；
- 提交产物（`.glb`）+ 生成脚本 + 预览图，三者缺一不可；
- 单个文件超过 50 MB 时不要直接提交，先考虑 Git LFS 或外部存储，并在该目录 README 里写明来源。

---

## 7. 外部参考代码

`_analysis/` 放的是第三方仓库的本地克隆（例如某个 CMS 的部署包），用来阅读、对照、评估。它已被根目录 `.gitignore` 忽略，因为它自带 `.git`，既不能作为子模块、也不该算作你的代码。

约定：

- 评估什么、结论是什么，写在**引用它的那个 idea 的 `IDEA.md`** 里，而不是放在 `_analysis/`；
- 需要长期引用时，在 `IDEA.md` 里记上游地址和版本，而不是把代码抄进仓库；
- 不要在广场根目录放第三方完整代码——会让仓库边界变模糊。

---

## 8. 提交习惯

- 一条提交只做一件事。跨 idea 的改动拆开提交。
- 前缀用目录名，扫描历史时一眼能看出影响面：`gold-miner: ...`、`docs: ...`、`template: ...`。
- 广场级改动用 `广场:` 或 `chore:`。
- 不提交：`node_modules/`、构建产物、浏览器 profile、`.env`、个人数据。已经在 `.gitignore` 里，别用 `git add -f` 绕过。

---

## 9. 每周十分钟巡检

固定每周做一次，只做判断，不做开发：

| 检查 | 动作 |
| --- | --- |
| 两周没动的 idea | 改 🅿️，写一句为什么停 |
| 「其实不想做了」的 | 改 🗄️ 归档，写下否决理由 |
| 已达毕业线的 | 走第 5 节拆出去 |
| 索引表和目录对不上 | 当场改表 |
| `IDEA.md` 的「下一步」全是旧的 | 重写，或者说明你为什么停在这里 |

**广场的价值来自诚实的状态，不是文件夹的数量。**
